# DSHA Root 命令限制与说明 · 2026-11-14

按用户本轮要求，在 2026-11-13 用户授权版基础上恢复受管 Root 命令限制。包名仍为 `dsh.android.client`，versionCode 190，诊断版本为 `0.2.1-rc.2-20261114.0530-root-guard-dsh0.2.1-rc.2`；Low 后缀为 `low`。使用既有 fork 固定证书，可覆盖本仓库上一版本，不能覆盖上游 E7E3 签名的安装。

- Root 只接受白名单内的单条命令，拒绝脚本、管道、重定向、未知执行器、分区写入、格式化、刷机、SELinux/系统属性和设置写入等操作。恢复文件操作的路径与描述符核验、停止应用的身份核验；系统应用和 DSHA 受保护。短信仅接受当前 Android 用户的严格查询，并要求独立原生授权。
- 检查覆盖自动选择的 Root、显式 `--su`、以 UID 0 运行的 Shizuku，以及实际为 Root 的 ADB 服务。Root 子进程执行前再次检查；被拒绝后不自动切换通道或重放。
- 开启 Root 前弹出独立说明，需要用户点击“了解限制并开启”。设备授权页可随时再次打开说明；拦截时弹出提示，后台拦截保留一个待提示标志，回到应用后展示，不保存原始命令。弹窗包含身份查询、文件读写、进程、设置和刷机等常用命令的用途及风险，没有绕过拒绝的按钮。默认消息区可滚动。
- 普通非 Root 通道、桥文件读取/导出/分享以及其他能力沿用上一版授权设置。Android 系统权限、连接授权、运行代次和备份事务继续生效。

这是 DSHA 受管入口的限制，不是 Root 管理器或内核沙箱。保留已披露的递归 READ 子链接覆盖缺口；自行运行的插件、shell 程序或其他应用不受这层检查约束。未将软件测试扩写成完整防绕过保证。

构建由本仓库 GitHub Actions 执行：两版 JUnit、Release Lint、受管输入与原生依赖检查、实际 APK 资产检查，以及固定证书和 v1/v2/v3 签名检查。最终结果、源码 commit、两版摘要以 Release 的 `build-receipt.json` 和对应 Actions 为准。新增回归使用假命令执行器、假 ADB 连接和 Robolectric，不执行被测危险命令。本轮禁止设备操作，未执行设备上的 LayoutAuditInstrumentation、安装、启动或真机验收。

本机清理已删除上一轮下载的五份 APK，以及可再生成的 Chromium、测试运行时和应急资产副本；保留源码、工具链、锁定构建输入、签名材料、历史对话及验收记录。GitHub 上的旧 Release 不删除。
